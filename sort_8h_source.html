37/*
38 * DCL delta -- retire <linux/minmax.h>'s swap() macro for this unit.
39 *
40 * Vendored lib/sort.c keeps a swap function pointer in a member named `swap`
41 * and calls it as `->swap(a, b, (int)size)` (sort.c:140). The preprocessor
42 * cannot tell a member call from an ordinary one, so minmax.h's two-argument
43 * swap(a, b) swallows that call and the build stops with "too many arguments
44 * provided to function-like macro invocation". mainline never meets this:
45 * its lib/sort.c opens with <linux/types.h>, <linux/export.h> and this
46 * header, and none of the three carries minmax.h. DCL's <linux/types.h> is
47 * a re-export of <linux/kernel.h> (types.h:49) and kernel.h:105 includes
48 * minmax.h, so every unit in the tree sees the macro.
49 *
50 * This header is where the retirement goes because it is the one header in
51 * that unit's include list that nothing else includes *for* the macro: the
52 * other two consumers of <linux/sort.h> (dma-fence-unwrap.c, drm_blend.c)
53 * call sort()/sort_r() with no swap function and never name swap() at all,
54 * while drm_crtc.c:688 and vkms_formats.c:267/:867-869 -- the calls the
55 * macro exists for -- do not include this header. Nothing in the tree today
56 * includes <linux/sort.h> and calls swap(); if one ever does, the failure is
57 * a compile error at the call, not a silent wrong expansion.
58 *
59 * The delta stays one block at the end so a re-port against a later kernel
60 * reads as upstream's file plus this.
61 */
62#undef swap

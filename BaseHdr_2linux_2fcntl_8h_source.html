4/*
5 * DCL <linux/fcntl.h> -- open(2) flags and the F_* commands.
6 *
7 * Ported from mainline's uapi/asm-generic/fcntl.h (what arm64 uses), values
8 * verbatim. The header exists because <linux/tty.h> tests file->f_flags:
9 * tty_io_nonblock() is `file->f_flags & O_NONBLOCK || ...`, and an undefined
10 * O_NONBLOCK would turn into an implicit declaration of an identifier the
11 * preprocessor never saw -- it would not be "always false", it would not
12 * compile.
13 *
14 * ---------------------------------------------------------------------------
15 * KNOWN DIVERGENCE, recorded here because the day it matters will be the day
16 * someone opens /dev/ttyS0 with O_NONBLOCK from userspace.
17 *
18 * Xeneva's userspace libc (Libs/XEClib/includes/fcntl.h) assigns a different
19 * bit layout entirely:
20 *
21 * userspace (XEClib) this header (asm-generic)
22 * O_NONBLOCK 0x0080 O_NONBLOCK 0x0800 (1 << 11)
23 * O_NOCTTY 0x0004 O_NOCTTY 0x0100 (1 << 8)
24 * O_RDWR 0x0800 O_RDWR 0x0002
25 * F_SETFL 0x0010 F_SETFL 0x0004
26 *
27 * This header follows mainline for two reasons: every ported file is written
28 * against mainline's numbers, and DCL's own cdev bridge already picked one --
29 * linux_cdev_shim.c:507 defines DCL_O_NONBLOCK as 0x800 with the comment
30 * "asm-generic fcntl.h: 00004000". Changing it now would silently change
31 * behaviour that already works.
32 *
33 * It is safe *today* because nothing yet carries a userspace flag into
34 * f_flags: there is no `f_flags =` assignment anywhere in the tree (the only
35 * writer is that cdev selftest, which ORs the value in by hand), so every
36 * open file reads as flags == 0 and the tty layer behaves blocking, which is
37 * the correct default. The reconciliation -- most likely teaching XEClib the
38 * Linux layout, since ported code assumes it -- belongs with the stage that
39 * first wires a real open() through to tty_open(). It is listed in the
40 * tracker rather than resolved here, because guessing which side should move
41 * without a working open path would be exactly that: a guess.
42 * ---------------------------------------------------------------------------
43 */

158/*
159 * Deliberately *not* <linux/types.h>, which mainline's fcntl.h does include.
160 *
161 * mainline needs it because the full uapi surface carries types: struct
162 * flock, struct f_owner_ex, flock64, struct falloc and the __kernel_* types
163 * they are built from. DCL's port is every #define above and nothing else --
164 * grep for a non-# line in this file and there are none -- so types.h was
165 * carrying nothing.
166 *
167 * It was carrying something, though, and it is worth recording why it is
168 * gone: types.h's only include is <linux/kernel.h> (types.h:21), which is the
169 * aggregator -- virtio.h, completion.h, wait.h, sched.h. So a header of
170 * numeric constants was reaching <linux/sched.h>, which `#undef current` and
171 * redefines the word as a macro. struct __VFS_NODE__ (BaseHdr/Fs/vfs.h:105)
172 * has a `uint64_t current` member, so a file that includes <Fs/vfs.h> after
173 * anything which touched this header came out with "field declared as a
174 * function" pointing at that member. linux_cdev_shim.c hit exactly that: it
175 * includes <linux/file.h> at line 9 and <Fs/vfs.h> at line 11, and file.h
176 * owes this header because mainline's fs.h includes it.
177 *
178 * If anyone adds struct flock or any other type here, <linux/types.h> comes
179 * back with it, and the collision comes back with that. The way round it
180 * then is to include <linux/fcntl.h> before <Fs/vfs.h>, not to make the
181 * member go away -- Xeneva's VFS layout is not this tree's to move.
182 */

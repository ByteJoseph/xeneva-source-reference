4/*
5 * DCL <linux/completion.h> -- struct completion and its two initialisers.
6 *
7 * virtio-rng.c reaches this header without naming it: mainline's
8 * <linux/virtio.h> includes <linux/completion.h> directly, and the driver
9 * declares `struct completion have_data` as a struct member. Getting the type
10 * from somewhere other than its own include is the point -- if DCL required
11 * the driver to include a header mainline does not, the vendored file would
12 * stop being byte-identical to upstream.
13 *
14 * ### The struct is one field, on purpose
15 *
16 * mainline's is:
17 *
18 * struct completion { unsigned int done; struct swait_queue_head wait; };
19 *
20 * `wait` is the wait-queue the blocked tasks queue on. DCL has no scheduler
21 * waiting to be woken: DCL/linux_kmod_shim.c's wait_for_completion_killable()
22 * polls, spinning on `done` while calling virtio_poll_vqs() so the virtio
23 * rings keep draining (which is also what makes the wait terminate -- the
24 * completion is signalled by random_recv_done(), a virtqueue callback, and
25 * that callback only runs from a poll). A wait-queue nobody blocks on would
26 * be a member every definition has to lay out and every field offset has to
27 * stay ahead of.
28 *
29 * The load-bearing part is that `done` is the FIRST member: the shim does
30 *
31 * *(unsigned int*)x = 1; -- complete()
32 * while (!*(unsigned int*)x) ... -- wait_for_completion_killable()
33 *
34 * -- it treats the pointer as a bare `unsigned int`. That is exactly
35 * `&completion->done`, which is only true while `done` is at offset 0. Move
36 * it and every complete()/wait pair in the tree starts racing on whatever
37 * object happens to follow.
38 *
39 * ### init/reinit are static inlines, as upstream has them
40 *
41 * (mainline: `static inline void init_completion(struct completion *x)`).
42 * They could be `((x)->done = 0)` macros; as functions they keep the
43 * argument typed, so passing anything but a `struct completion*` is an error
44 * instead of a quietly-wrong dereference. Being `static inline` they also do
45 * not drag an unused-function warning along when a file includes this header
46 * and uses neither.
47 */

79 * Both are defined in DCL/linux_kmod_shim.c. Declared with these types rather
80 * than `void*` so the definition and every caller agree -- an earlier
81 * arrangement had the shim taking `void*`, which links fine (C has no name

84 *
85 * wait_for_completion_killable() returns 0 on success or -ERESTARTSYS. It

88 * the boot.

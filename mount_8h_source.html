15/*
16 * Two mainline headers, neither of which mainline's own mount.h carries. They
17 * come in here because this file is where drm_drv.c already reaches the
18 * mainline fs.h surface that DCL's pinned <linux/fs.h> cannot hold --
19 * simple_pin_fs(), simple_release_fs() and unmap_mapping_range() below are all
20 * mainline fs.h functions, and the pinned fs.h is an ABI blob of struct
21 * layouts with no room to declare them.
22 *
23 * drm_drv.c names this header directly (drm_drv.c:36) and that is the only
24 * route into it in the whole drm set: drm_device.h includes it too, but
25 * behind `#ifdef CONFIG_TRANSPARENT_HUGEPAGE` (drm_device.h:5), which is off.
26 * So a symbol put here is visible to drm_drv.c and to nobody else, which is
27 * why the two below are here and O_CLOEXEC is not.
28 *
29 * <linux/kernel.h> comes first and is not a mainline mount.h include either --
30 * it is here for what this file now defines. noop_llseek() returns loff_t and
31 * kdev_t.h's helpers take dev_t, and both types live in kernel.h; fs.h carries
32 * neither (it defines the file and inode *layouts* and nothing else), so
33 * without this include the header depends on its includer having pulled
34 * kernel.h already, which is true of mm.h and untrue of drm_drv.c.
35 *
36 * <linux/kdev_t.h> MINORBITS, for DRM_EXTENDED_MINOR_LIMIT (drm_drv.c:141).
37 * mainline reaches it because fs.h includes kdev_t.h; the
38 * pinned fs.h defines MKDEV/MAJOR/MINOR with the bit count
39 * spelled inline and never names the macro.
40 * <linux/sizes.h> SZ_8, for the bits-to-bytes pitch rounding in
41 * drm_dumb_buffers.c:180.
42 *
43 * noop_llseek() comes from further down this file rather than <linux/mm.h>,
44 * where it used to be: mm.h includes mount.h (for the VFS block below), so

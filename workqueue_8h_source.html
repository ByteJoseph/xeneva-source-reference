37/*
38 * Work runs inline: there is no kworker to run it later.
39 *
40 * These are functions, not statement-expressions, because mainline's callers
41 * use their return values -- tty_buffer.c:66 is literally
42 * `return queue_work(flip_wq ?: system_dfl_wq, &buf->work);`, which does not
43 * parse against a do{}while(0) macro. The bool is "work was queued"; since
44 * it runs to completion before we return, true is always the right answer.
45 *
46 * Inline execution is a real deviation from mainline and it is worth being
47 * precise about why it is safe here: tty_flip_buffer_push() calls this from
48 * interrupt context, so flush_to_ldisc() runs before tty_flip_buffer_push()
49 * returns rather than on a worker later. Its only lock is the buffer mutex,
50 * which in DCL is a no-op (<linux/mutex.h> says so plainly), so there is
51 * nothing to deadlock on. This is also what Linux itself did before 2.6.24,
52 * when tty_flip_buffer_push() called the flush directly. The behaviour that
53 * changes is latency, not correctness: a byte arrives at n_tty before the
54 * interrupt handler returns instead of after.
55 */

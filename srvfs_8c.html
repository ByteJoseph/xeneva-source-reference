srvfs.c – /srv, a file system served by a user-space process.

The kernel keeps no file data and no directory: every open/read/write on a /srv path becomes a request to the IPC endpoint "fs" (BaseHdr/fssrv.h), stamped with the caller's uid. The server (Process/fssrv) owns the namespace.

The hard part is waiting. A syscall that sleeps does not return up the C stack: the thread resumes after the svc instruction. So a proxy operation that has to wait for the server does this instead:

  1. first execution: queue the request, remember it, rewind ELR_EL1 by one instruction and sleep – the thread resumes by re-executing the svc;
  2. re-execution: the syscall runs again from its entry. Each proxy operation is matched, in order, against this thread's history for the syscall; a finished one returns its saved answer without asking the server again, a pending one polls (and sleeps again if still unanswered).

Positions are restored on replay so side effects of an earlier pass are not applied twice. The history is dropped when the syscall finally returns (the dispatcher calls AuSrvfsSyscallExit). A request the server does not answer in SRV_TIMEOUT_MS fails with an error, so a dead or stuck server never hangs a client. Reads and writes move at most one page per operation.

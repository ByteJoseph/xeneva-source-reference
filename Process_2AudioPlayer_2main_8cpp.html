Accent – XenevaOS music player, Windows 8 "Metro" style

rootLayout (BorderLayout) client area |- TOP AcHeader "music" library | now playing (pivots) |- CENTER AcPages library: flat tiles, horizontal scroll | now playing: tile, title, spectrum, progress `- BOTTOM AcAppBar track | (prev) (play/pause) (next) | time

Audio runs on its own thread (engine.h). This file is the UI thread: it never decodes, never writes to the sound device and never blocks on the engine. It reads the engine's lock-free shared block once per tick.

Visualizer budget: a 512 point FFT plus incremental bar drawing (only the pixels between a bar's old and new height are touched) and one dirty rectangle per frame, at ~30 fps. The engine gives the CPU away for a few ms after every device write; that window is enough for a frame.

Launcher: while a song plays, its title / artist / progress go to the XELnch "accent" tile (livetile.h): once per second of playback, at once on a track change or pause, and the tile is cleared when playback stops or the window closes.

Album art: the ID3 tag walk that reads title / artist / album also notes where the first picture frame is. A baseline JPEG there is decoded once per track (nanojpg.h) and kept only as the square the now-playing page shows, area-averaged to its exact size; the decoder's buffers are freed at once. Anything else (PNG, progressive JPEG, no picture) keeps the coloured tile.

Launch: "accent /path/song.mp3" (any argv slot – static images see the arguments as passed, dynamic ones get the exe path prepended by xeldr) opens the song's folder as the library and starts playing it.

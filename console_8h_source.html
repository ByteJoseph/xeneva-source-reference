4/*
5 * DCL <linux/console.h> -- the console registration surface serial_core and
6 * 8250 use.
7 *
8 * The load-bearing decision here: register_console() records a console so
9 * that console_is_registered() answers true and callers stop asking -- but it
10 * does *not* hand the UART over. Xeneva's boot log is written to the same
11 * serial port by UARTDebugOut(), and letting mainline's uart console drive
12 * those registers as well would mean two writers interleaving characters at
13 * register level: a garbled console rather than a working one, and a fault
14 * that would only show up under load. Native output keeps ownership; the
15 * registration API is satisfied because serial_core.c:2574 calls
16 * register_console() and then expects console_is_registered() to be true, and
17 * because uart_add_one_port() returns through it (serial_core.c:2991, :2999).
18 *
19 * console_lock()/console_unlock() are the printk console semaphore. There is
20 * exactly one writer here, so the lock is uncontended by construction -- but
21 * they must exist as calls, because serial_core.c:2530 and tty_io.c:3589 take
22 * them around tty-device lookups, and a missing symbol would take the whole
23 * registration path down.
24 *
25 * console_suspend() is called from uart_suspend_port()/uart_resume_port();
26 * Xeneva has no suspend path, so it is a no-op that keeps the call site
27 * readable rather than sending anyone to find out why the symbol is missing.
28 *
29 * console_suspend_enabled mirrors mainline's default for a kernel without
30 * CONFIG_PM_SLEEP: false. serial_core.c:2319 branches on it -- with false the
31 * suspend path stops RX and returns early, which is the behaviour that makes
32 * sense for a console that is never suspended.
33 */

82/*
83 * console_is_registered_locked() -- the same answer as
84 * console_is_registered(), taken with the console list lock held.
85 *
86 * mainline splits these because the unlocked one has to take a lock itself,
87 * and calling it while already holding it would deadlock. DCL's
88 * console_lock()/console_unlock() are empty (DCL/linux_irq_shim.c) and the
89 * registry is a plain array scan, so there is no lock to re-enter and no
90 * separate locked path to maintain -- one body, two names, and the reason the
91 * second one does not take a lock is that neither does the first.
92 *
93 * The caller is uart_console_registered_locked() in serial_core.h:1376, which
94 * asks whether the port's console is on the list while already holding the
95 * port lock. Answering the same thing twice under two names is fine;
96 * answering it differently would be the bug.
97 */
98static inline bool console_is_registered_locked(struct console* con)
99{
100 return console_is_registered(con) != 0;
101}

105 * header already declares. It is called with console_suspend_enabled

107 * CON_SUSPENDED/CON_ENABLED bookkeeping suspend() did.

109 * DCL has no suspend path -- console_suspend() is a body in

113 * mainline's is, the body goes beside console_suspend()'s so the pair stays

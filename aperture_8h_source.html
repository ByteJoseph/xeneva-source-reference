6/*
7 * DCL <linux/aperture.h> -- upstream's header, including the shapes that
8 * matter here: CONFIG_APERTURE_HELPERS is not defined in this tree, so the
9 * #else arm below is the live code and every entry point answers 0.
10 *
11 * That is not a shortcut around mainline's logic, it is the same answer a
12 * mainline build without the option gives: aperture helpers are how one
13 * driver evicts another's firmware framebuffer from the PCI BARs they share
14 * (the simpledrm/efifb/vesafb conflicts). This target's boot console is
15 * Xeneva's own GOP framebuffer on its own device, not a PCI driver, and the
16 * DRM device a vendored driver claims (bochs) never overlaps it -- there is
17 * nothing to evict and no registry to evict it through. The return value is
18 * what every call site tests before proceeding, so 0 keeps the driver on its
19 * happy path, exactly as it would be on mainline.
20 *
21 * Kept as inline functions rather than deleted declarations so that a
22 * driver's `aperture_remove_conflicting_pci_devices(pdev, name)` call site
23 * compiles without a DCL shim symbol behind it.
24 */

54 * Mutation -- added for <linux/wait.h>, which keeps its queues in these
55 * lists. DCL had only the iteration macros, so a wait queue would have had
56 * nowhere to put an entry.
57 *
58 * LANDMINE, recorded so nobody has to rediscover it: Xeneva's own
59 * <list.h> -- a different, older API over `list_t` -- also exports a
60 * `list_add(list_t*, void*)`, and the two cannot be declared in one
61 * translation unit (they are both `list_add`, with different arguments; C
62 * has no overload). Nothing in the ported tty/serial set includes that
63 * header, so they coexist in the tree -- but a file that needs Xeneva's
64 * process/socket/network headers *and* a mainline list has to be split in
65 * two, or one of the two APIs renamed. DCL/linux_irq_shim.c takes the first
66 * route: it reads the process name from AA64Thread rather than pulling in
67 * <process.h>, which drags the native one along.
68 *
69 * list_del() is deliberately idempotent: it clears the node and a second
70 * remove on an already-removed node is a no-op rather than a write through
71 * stale pointers. Mainline poisons the node instead, to catch the bug -- a
72 * reasonable trade when a mistake trips a debug kernel, but the wrong one
73 * here, where a doubly-removed wait entry would corrupt a queue that nothing
74 * else is checking, on a system with no lock protecting it either way.

134 * list_is_head() / list_is_singular() / __list_cut_position() /
135 * list_cut_position() -- mainline's, verbatim, for virtio_console.c:393:
136 *
137 * list_cut_position(&tmp_list, &pending_free_dma_bufs,
138 * pending_free_dma_bufs.prev);
139 *
140 * which cuts the whole pending-free list off under the lock so the buffers can
141 * be released without it held. The four travel together because
142 * list_cut_position() is the only *entry point* but cannot be written without
143 * the other three: it asks list_is_singular() whether there is exactly one
144 * entry (in which case cutting is a no-op unless entry is the head),
145 * list_is_head() whether entry names the head rather than a member, and
146 * __list_cut_position() does the relinking.
147 *
148 * The detail that makes __list_cut_position() worth copying rather than
149 * re-deriving is `new_first`: entry->next is read into a local *before*
150 * `entry->next = list` overwrites it, so head's new first element is the one
151 * that followed the cut point rather than the cut point's own list member.
152 * Getting that order wrong produces a list that is self-consistent, silent,
153 * and wrong -- the failure mode list debug code exists to catch and DCL does
154 * not have.
155 *
156 * mainline: include/linux/list.h:480-522.

902/*
903 * nbcon (the atomic console) is reduced to its non-nbcon answer.
904 *
905 * mainline decides, on every port lock, whether the console attached to the
906 * port is an atomic one -- CON_NBCON with a ->write_atomic, on the console
907 * list -- and if so takes the console's own atomic context around the lock.
908 * DCL has none of that: no CON_NBCON, no ->write_atomic, no nbcon_device_*
909 * anywhere in BaseHdr, and a struct console whose only output path is ->write,
910 * which must not be reentered. The port lock is precisely what serialises it.
911 *
912 * What matters for the vendored sources is that the WRAPPERS stay callable
913 * with mainline's signatures -- uart_port_lock(), uart_port_lock_irq(),
914 * uart_port_lock_irqsave() and the guard definitions below all route through
915 * these three, and 8250_port.c / serial_core.c are compiled byte-identical to
916 * upstream. So the shapes are kept and only the answer changes, and `false`
917 * is not a stub standing in for unimplemented behaviour: it is mainline's own
918 * first branch for any console that is not CON_NBCON, which is every console
919 * DCL can register. The nbcon arms are unreachable rather than approximated.
920 *
921 * If DCL ever grows an atomic console this is the function to restore -- the
922 * call sites never changed, so only the bodies have to come back.
923 */

927 return false;
